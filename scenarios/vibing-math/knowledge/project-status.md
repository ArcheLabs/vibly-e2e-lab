# Project Status

## Phase

The Goldbach Program is in the bootstrap research-base phase.

The project is not ready for direct final-proof attempts as its primary activity. It first needs shared research infrastructure: literature structure, taxonomy, failed-path memory, review standards, and artifact templates.

## Primary Goal

Build durable knowledge assets that allow future agents to work cumulatively.

The primary goal is to reduce future search cost. Each accepted contribution should make at least one of the following easier:

- selecting a useful next task;
- avoiding a repeated failed route;
- evaluating a mathematical claim;
- locating relevant literature;
- comparing proof strategies;
- distinguishing heuristics from verified results;
- identifying a narrow exploratory direction.

## Current Assets

The project currently has:

- a basic statement of Goldbach's conjecture;
- a list of broad research directions;
- an acknowledgment that reusable research infrastructure is more important than immediate proof attempts;
- an empty structured literature index placeholder.

## Missing Assets

The project currently lacks:

- a structured literature index;
- a proof-attempt taxonomy;
- a failed-path archive;
- a review rubric;
- artifact templates;
- a computational verification map;
- a partial-results map;
- a route comparison map;
- a knowledge promotion policy;
- a shared claim-level discipline.

## Immediate Priorities

Agents should prioritize:

1. building the literature index schema and initial entries;
2. classifying proof approaches and known obstructions;
3. creating failed-path archive entries;
4. creating reviewable artifact templates;
5. summarizing partial results and their limitations;
6. creating a computational verification map;
7. designing exploratory tasks with bounded scope.

## Evaluation Focus

The project should evaluate contributions by their ability to compound.

High-value artifacts are:

- structured;
- reviewable;
- non-duplicative;
- reusable;
- cautious about claim level;
- clear about limitations;
- connected to the project knowledge base.

## What Not To Do Yet

Agents should not make direct final-proof claims unless the artifact contains a complete, reviewable proof at the appropriate claim level.

Agents should not:

- treat heuristics as theorems;
- treat computation as a general proof;
- invent citations;
- duplicate existing work;
- propose broad tasks without artifacts;
- hide failure points;
- omit limitations.

The near-term objective is not glory. It is shared memory.
