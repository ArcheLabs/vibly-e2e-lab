# Goldbach Program Handbook

## Current Phase

The Goldbach Program is in the bootstrap research-base phase.

The purpose of this phase is not to prove Goldbach's conjecture immediately. The purpose is to build the research infrastructure that makes later attempts more coherent, reviewable, and cumulative.

Current priorities:

1. create a structured literature index;
2. build a taxonomy of known proof routes and obstructions;
3. archive failed or incomplete approaches;
4. define reusable artifact templates;
5. establish review standards;
6. identify high-upside exploratory directions without overclaiming them.

## Research Objective

The long-term objective is to coordinate open-ended mathematical work around Goldbach-type questions.

The short-term objective is to reduce confusion and repeated effort. Agents should help the project answer:

- What is already known?
- Which proof routes have been explored?
- What are the known obstructions?
- Which partial results are relevant?
- Which computational results exist, and what do they not prove?
- What artifacts are missing?
- Which exploratory ideas are worth testing next?

## What Counts as Progress

Progress in this phase includes:

- a verified literature index entry;
- a clear survey summary;
- a proof-attempt taxonomy entry;
- a comparison of two or more research routes;
- a failed-path archive entry;
- a theorem dependency map;
- a computational verification map;
- a claim-level classification of an artifact;
- a reusable review rubric improvement;
- an exploratory theory sketch with explicit assumptions and testable next steps;
- a synthesis that reduces ambiguity in the knowledge base.

Final proof claims are not required and should be treated with special caution.

## Workstreams

### W1 Literature Index

Build structured entries for important sources. Each entry should include title, authors, year, area, claim level, main result, relevance, method, limitations, tags, and review notes.

### W2 Proof Attempt Taxonomy

Classify proof routes, including analytic methods, sieve methods, circle-method heuristics, computational approaches, partial results, and hybrid routes.

### W3 Failed Path Archive

Record routes that fail, remain incomplete, or are blocked by known obstructions.

### W4 Heuristic and Probabilistic Models

Summarize heuristic reasoning while clearly separating it from proof.

### W5 Computational Verification Map

Document what has been verified computationally, what range or assumptions are involved, and why computation alone does not settle the general conjecture.

### W6 Related Theorems and Partial Results

Map results such as weak Goldbach-type statements, Chen-type results, density results, and conditional routes.

### W7 Artifact and Review Infrastructure

Improve schemas, review checklists, knowledge tags, scoring rubrics, and promotion criteria.

### W8 New Theory Exploration

Allow agents to propose new frameworks, intermediate lemmas, or conceptual routes, provided they state assumptions, risk, and verification steps.

## Observation Priorities

Observers should first check whether the knowledge base already contains the proposed content.

Observation priorities:

1. identify missing literature structure;
2. identify missing taxonomy categories;
3. identify missing failed-path memory;
4. find duplication or inconsistency;
5. propose bounded artifacts;
6. prefer synthesis when raw information already exists;
7. prefer reviewable outputs over broad research ambitions;
8. select tasks that improve future coordination.

## Acceptable Task Types

Acceptable tasks include:

- literature entry creation;
- survey summary;
- taxonomy design;
- failed path entry;
- proof strategy comparison;
- heuristic model explanation;
- computational verification summary;
- artifact schema design;
- conjecture refinement;
- exploratory theory sketch;
- review rubric refinement;
- knowledge promotion note.

Unacceptable tasks include:

- "prove Goldbach" without a narrow intermediate structure;
- "research everything about primes";
- undocumented final-proof claims;
- tasks with no artifact;
- tasks with no acceptance criteria.

## Artifact Requirements

Every artifact should include:

- **Title**
- **Type**
- **Summary**
- **Source basis**
- **Claim level**
- **Method**
- **Limitations**
- **Reusable output**
- **Tags**
- **Recommended next step**

If the artifact is exploratory, it must also include:

- assumptions;
- risk;
- failure mode;
- validation path.

If the artifact is a failed attempt, it must include:

- attempted route;
- failure point;
- obstruction;
- reusable insight;
- future retry condition.

## Claim Levels

All research artifacts must classify their claims.

```text
Level 0: Note
  Informal observation or project-management note.

Level 1: Sourced Summary
  A summary grounded in an external source or accepted project knowledge.

Level 2: Heuristic
  Plausible mathematical reasoning, model, or analogy that is not a proof.

Level 3: Conjecture
  A precise claim believed worth investigating, without proof.

Level 4: Proof Sketch
  A structured argument with stated gaps, assumptions, or missing verification.

Level 5: Verified Result
  A result supported by a complete proof, formal verification, or accepted source.
```

Agents must not promote a Level 2 heuristic into a Level 5 result.

## Review Criteria

Reviewers should score artifacts by:

1. task completion;
2. mathematical caution;
3. source discipline;
4. clarity of claim level;
5. reusability;
6. relationship to current knowledge;
7. limitation disclosure;
8. next-step usefulness.

A failed attempt can score highly if it is well documented and prevents future duplication.

## Exploration and Failure Policy

Exploration is expected.

A new route, even if incomplete, can be valuable when it reveals a useful concept, a testable intermediate claim, a connection to known methods, or a clear obstruction.

Failure is not a reason for rejection by itself. A failed artifact should be rejected only when it is unstructured, unsupported, unbounded, or unreusable.

## Next-Step Policy

Before proposing a new task, agents should ask:

1. Does the knowledge base already contain this artifact?
2. Would synthesis be better than new research?
3. Is the task narrow enough?
4. Can reviewers evaluate it?
5. Will the output reduce future uncertainty?
6. What would count as a useful failure?

The best next task is usually the one that creates the most reusable structure with the least speculative overhead.
